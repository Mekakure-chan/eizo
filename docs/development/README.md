# 映蔵｜埋め込み動画保存

デスクトップ版Google Chrome 109以降用の拡張機能です。先に保存フォルダーを選んでおくと、動画ページで検出したHLSやMP4などの動画ファイルをワンクリックで取得し、そのフォルダーに自動保存します。元タブには取得と保存の進捗が出て、完了すると「保存済み」に変わります。

## Chromeに追加する

1. Chromeのアドレスバーに `chrome://extensions` と入力します。
2. 右上の「デベロッパー モード」をオンにします。
3. 「パッケージ化されていない拡張機能を読み込む」を押し、`manifest.json` が入っている `extension` フォルダーを選びます。ZIP版は先に全体を展開してください。すでに同じフォルダーから前版を読み込んでいる場合は、拡張の「再読み込み」（↻）を押すと更新されます。
4. ツールバーのパズル型アイコンから「映蔵｜埋め込み動画保存」を固定すると、動画ページからすぐに開けます。読み込んだフォルダーはその場所に置いてください。

## ダウンロードキューを使う

1. 「ダウンロード一覧」の **「保存先を指定」** で、最初のフォルダーを登録します。**「保存先を追加」** で合計3か所まで登録できます。使いたいフォルダー名を押すと、その名前の横に **「自動保存」** と表示され、保存待ちの動画の書き出しが始まります。以前のバージョンで指定したフォルダーは、選択中の保存先として引き継ぎます。
2. 動画ページで **拡張アイコン** を押します。候補が1つなら取得が始まります。複数の独立した配信があるときは対象を選びます。HLSや動画ファイルの取得中・保存待ちにもう一度アイコンを押すと、同じ取得状況を表示します。個別キューを見たいときは右上の「キューを開く」を押します。
3. キューのタブ名の先頭に、アーカイブなら **「50% 取得中」**、ライブなら **「12区間 取得中」** のように表示されます。映像と音声が別配信のライブは両方の取得済み区間の合計です。元ページに進捗パネルが出ている間は、そのタブ名にも「DL中」と進捗が表示されます。キューには元ページへのリンクがあり、「ダウンロード一覧」からは他のページの進捗も確認できます。
4. 保存先を指定してある場合、取得が終わるとそのフォルダーへ書き出しが始まります。HLSの保存名には元ページのタイトルを使い、同名なら「 (2)」「 (3)」と連番を付けます。書き込みが完了すると「保存済み」になり、個別キューを開いていた場合はそのタブが閉じます。

「ダウンロード一覧」では、各行から保存・中止・再取得ができます。ライブの「取得を停止」は、そこまでに取得した区間を保存待ちにします。「保存を中止」は取得済みの動画をキューに残します。動画タイトルを押すと個別キューを表示できます。

2か所目と3か所目は、登録したあとフォルダー名を押した時点で切り替わります。「書き出し待ち」「保存中」「保存済み」の行には、その動画の保存先が表示されます。書き出し待ちか保存中の動画は、切り替え前の保存先に書き出します。同じ名前のフォルダーは登録番号で区別します。

**「毎回選ぶ」** を押すと登録したフォルダーを覚えたまま、自動保存を休止します。フォルダー名を押すと再開します。**「登録先を管理」→「登録を解除」** で空きを作れます。選択中の登録を解除すると「毎回選ぶ」に戻ります。

一覧には、取得・保存中や操作待ちの動画、再取得できるエラーが先に並びます。保存済み・キャンセル・結合失敗はその下で確認できます。複数の状態が混在するときは、件数のある状態を押して絞り込めます。「すべて」で全件表示に戻れます。

「元タブを閉じる」を押すと、その動画を取得したタブだけを閉じます。書き出し待ち・保存中でも保存は続きます。元タブでの取得や録画が必要な間、このボタンは無効です。元タブが別ページに移った場合や、同じURLを再読み込みした場合はボタンが消えます。

ストレージへの書き出しは、自動保存と手動保存を合わせて**1本ずつ**行います。5本まとめて保存すると、1本が保存中、残り4本が「書き出し待ち」になります。先のファイルの保存が確定すると、次の動画が自動で進みます。その間も動画の取得や一覧の操作は続けられます。

元タブと一覧には、保存中の進捗率と「動画ファイルをストレージに保存しています。」が表示されます。「毎回選ぶ」で保存先を選ぶ前は「保存準備中」と表示します。指定フォルダーへの書き込みが終わると「保存を確定中」、保存先が完了を返すと「保存済み」になります。保存を中止できるのは、ファイルの確定に入るまでです。

書き込みに失敗した動画は、一時ファイルがキューに残るので保存をやり直せます。フォルダー名に **「書き込み許可が必要」** と出たら、一覧の **「自動保存を許可」** を押します。継続して使う場合は、Chromeが継続許可の選択肢（英語表示では **Allow on every visit**）を出したときに選んでください。取得済みの動画もそのまま保存されます。個別キューでは **「保存先を再許可して保存」** でも同じ操作ができます。 [Chromeのフォルダーアクセス許可](https://developer.chrome.com/blog/persistent-permissions-for-the-file-system-access-api?hl=ja)

**「毎回選ぶ」** を選んだ場合と保存先が未指定の場合は「保存待ち」で止まります。「保存」を押すと名前を付けて保存する画面が開き、キャンセルすると保存待ちに戻ります。別の拡張がダウンロード名の決定に参加すると、Chromeが英数字のファイル名を提示する場合があります。指定フォルダーへの自動保存には元の動画名が使われます。 [ChromeのダウンロードAPI](https://developer.chrome.com/docs/extensions/reference/api/downloads)

元ページから直接取得するMP4などの動画ファイルは、取得中に元タブを閉じても最後まで進みます。HLSは、元のプレーヤーが必要な間だけパネルに「このタブを開いたままにしてください」と表示します。どちらも「保存待ち」になったら元タブを閉じられ、同じChromeセッション中は「ダウンロード一覧」から保存できます。全編保存のPCツール・再生区間のキャプチャ・手入力で開始した取得では、取得中は個別キューを開いておいてください。一覧タブで取得を引き継いだ場合は、その行に一覧を開いたままにする案内が出ます。ブラウザーを完全終了したり拡張を更新したりする前に、残したい動画を保存してください。動画は拡張の一時領域に置き、キューと元ページの情報はChromeのセッションストレージに記録します。 [Chromeのセッションストレージ](https://developer.chrome.com/docs/extensions/reference/api/storage#property-session)

### タブのアイコンで状況を確認する

元ページと個別キューに同じ状態アイコンが出ます。タブにポインターを置くと、状態名と動画タイトルを読めます。

| タブのアイコン | 状態 |
| --- | --- |
| 青い下矢印 | 配信元からダウンロード中、または再生区間を録画中。取得率やライブの区間数はタブ名に出ます。 |
| 紫の横長ドライブ | 取得した動画ファイルを準備中、ストレージに保存中、または保存を確定中。 |
| 橙の一時停止マーク | 書き出しの順番待ち、保存先の選択や許可などの操作待ち、中止、または取得率や区間数が約1分間更新されていない状態。タブ名で理由を確認できます。ライブの一部だけを保存できる場合は「一部取得・保存待ち」と表示します。 |
| 赤い感嘆符 | エラー・中断。パネルまたは個別キューに理由が出ます。 |
| 緑のチェック | 取得完了・保存待ち。自動保存が有効なら書き出しに進みます。「毎回選ぶ」の場合は「保存」を押します。 |
| グレーのディスク | ファイルの保存完了。元ページのパネルが閉じたあとも、別のページへの移動か再読み込みまで印が残ります。 |

サイトが独自アイコンの読み込みを制限している場合は、サイトのアイコンを保ち、タブ名に状態を表示します。

## HLSのライブ・アーカイブを保存する

1. 初回は拡張アイコンを開き、**「HLSの自動検出」→「自動検出をオン」** を押し、Chromeの確認画面で許可します。ページとは別のドメインにあるプレーヤーや配信サーバーも検出するため、HTTP・HTTPSサイトの読み取り許可を使います。すでに開いていた動画ページは再読み込みしてください。再生開始時に初めて配信を読み込むサイトでは、再生を押すと検出できることがあります。
2. アイコンに赤い **「HLS」** が付いたらクリックします。配信が1つならそのまま取得が始まります。キューは **「キューを開く」** を押したときに表示します。同じマスターに属する映像と音声は1候補にまとまり、取得画面に音声名とそれぞれの区間数が表示されます。独立した配信が複数ある場合は「取得を開始」で対象を選びます。
3. **アーカイブ**は全区間を取得した後、指定フォルダーにMP4を書き出します。プレーヤーを最後まで再生する必要はありません。
4. **ライブ**は、取得を始めた時点で配信元に残っている最も古い区間から新しい区間を追います。元ページ右上かキューで **「取得を停止」** を押すか、配信元が終了を知らせると、取得できた区間を指定フォルダーに保存します。「毎回選ぶ」の場合は、取得終了後に「保存」を押します。

元ページ右上とキューに、元タブをいつ閉じられるか表示します。

- **「このタブは閉じられます」** と出た場合は、Chrome内のバックグラウンド処理だけで取得を続けられます。
- **「保存待ちまでこのタブを開いたままにしてください」** と出た場合は、配信を検出したプレーヤーをそのまま使います。「保存待ち」になるまで、そのページを閉じたり、再読み込みしたり、別の動画へ移動したりせずにお待ちください。動画の再生操作は不要です。

取得方法は自動で決まります。ライブの **「取得を停止」** や保存も右上のパネルで操作できます。追加の配信元に読み取り許可が必要なときは、同じタブで拡張アイコンを押し、**「許可して取得」** を選びます。元ページにパネルを表示できない場合は、拡張の **「キューを開く」** から進捗を確認できます。

取得中にプレーヤーが再読み込みされた場合、取得済みの区間を保持して書きかけの区間を取り直します。元タブがなくなり、配信元がキューからの取得も拒否した場合はキューに理由が表示されます。同じ区間の接続が繰り返し切れた場合、自動再試行は最大2回です。

URLを入力する場合は **「m3u8のURLを指定」** を開きます。映像と音声が載っているマスターのURLなら、1つ入力するだけです。個別のURLが手元にある場合は、上段に映像のm3u8、下段に音声のm3u8を入力します。自動検出がオフのときは、必要な配信元のアクセス許可を個別に求めます。「自動検出をオフ」で自動検出用に追加した全サイトの許可を解除できます。

ライブ冒頭がすでに配信元の一覧から消えている場合、取得できるのは残っている範囲からです。通信やPCのスリープで区間が抜けた場合は、連続して取得済みの部分を保存できます。理由は取得画面に表示します。 [HLSのライブ配信に関する仕様](https://www.rfc-editor.org/rfc/rfc8216.html#section-6.2.2)

別配信の場合は、映像と音声をChromeの一時領域に取り込み、両方のトラックを1本のMP4に書き込みます。保存が成功すると、この取得の一時ファイルを削除します。映像・音声を含むTSを元の形式で保存したいときは、取得前に「毎回選ぶ」に切り替え、取得後に「元のTSを保存」を選んでください。

### HTTP 403 が出たとき

HLSアーカイブで映像・音声の一部の区間が403を返したときは、自動でその区間を飛ばして取得を続けます。それまでに取得した区間はそのまま使います。取得が止まった場合は、キューに応答を返したホスト名、失敗箇所、取得経路（「プレーヤー経由」または「拡張から直接」）が表示されます。 [Chrome拡張のネットワーク通信](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)

区間エラーで停止した場合、元タブのパネルとキューには「7/9 区間目（再生位置 0:51 付近）」のように表示されます。ライブでは取得開始からの時間が表示されます。

マスタープレイリストに映像の解像度がある場合は、動画区間のエラーに「取得画質 1280×720」のように表示します。元タブで画質を選び直した場合や、旧版で止まった配信を再度取得する場合は、プレーヤーに映像が出た状態で拡張アイコンを押すと、その時点の画質と配信候補を調べて取得を始めます。

ダウンロード一覧の **「HLSの欠損区間を自動でスキップ」** は更新後からオンになります。区間エラーで停止させたい場合はオフにしてください。設定は次に開始する取得と再取得に適用されます。オフで停止した動画も、エラー画面の **「欠損区間をスキップして再取得」** でその動画だけ再取得できます。

対象は、アーカイブのプレイリストに載っている映像・音声区間です。配信元が欠落を明示した区間、403・404・410を返す区間、形式や長さの検査に失敗した区間を除きます。取得できた前後は1本のMP4につなぎ、保存名に **「（欠損あり）」** を付けます。一覧と個別キューには、元の動画で省いた区間番号と時間帯が残ります。映像の再開にキーフレームが必要な場合は、再生を始められる位置まで調整します。

プレイリストや初期化データを取得できない場合、ログインが必要な場合、保存可能な区間が残らない場合はエラーを表示します。元タブを閉じた後に配信元が直接取得を拒否し、続きを読めなくなった場合は、キューに元ページでの再検出を案内します。

取得した区間の再生時刻が前後している場合など、MP4に結合できないときは **「結合に失敗しました」** で終了します。ダウンロード一覧の「中断・エラー」に理由が残り、その動画の一時ファイルは削除されます。保存先の空き容量や書き込み許可が原因の場合は「保存待ち」に戻るので、原因を解消した後に保存し直せます。

**元の配信を確認する場合**は、次の操作を使えます。

1. 元タブの **「配信を再検出」** を押すと、現在の配信候補が開きます。個別キューの **「元ページで再検出」** からも開けます。元タブを閉じていた場合は、キューの **「元ページ」** リンクから動画を開き直し、そのタブで拡張アイコンを押します。
2. 候補画面に戻って **「再検出」** を押します。新しいURLが出たら **「新しく検出したURLで取得」** を選びます。同じURLを試す場合は **「前回のURLで再取得」** を選びます。
3. 拒否が続き、元ページで動画を再生できる場合は **「再生区間をキャプチャ」** で録画画面を開けます。録画を開始してから再生した区間が保存されます。

## 対応サイトの動画を再生せずにMP4で全編保存する

1. 初回は、拡張フォルダーの隣にある `Windows-Setup.cmd` をダブルクリックします。64ビットWindowsのユーザー領域に保存ツールを配置し、このフォルダーの拡張IDをChromeに登録します。初回取得は約143 MBです。
2. YouTubeなどの動画ページを開き、拡張アイコンを押します。候補を選ぶ画面が開いた場合は **「丸ごと保存」** を押します。動画は一時停止のままで構いません。YouTubeの埋め込みやShorts、対応サイトの埋め込みプレーヤーも、動画IDを特定できれば候補に表示します。
3. 初回はキューの「許可して取得」を押し、PCの保存ツールとの接続をChromeで許可します。
4. キューを開いたまま完了を待ちます。元の動画タブは閉じられます。映像と音声を結合して確認した後、指定フォルダーにMP4を書き出します。「毎回選ぶ」の場合は、キューの「保存」を押します。

「丸ごと保存」の対象はYouTube、ニコニコ動画、Dailymotion、Vimeoの個別ページにある公開済みのオンデマンド動画です。この機能ではログイン必須・DRM保護・地域制限・配信元が取得を拒否した動画や、進行中のライブは対象外です。取得と結合には一時ディスク領域を使います。

保存ツールは拡張の要求時に起動し、ブラウザーのログイン情報を読み取りません。セットアップは固定した配布版をSHA-256で確認します。使用するのは [yt-dlp](https://github.com/yt-dlp/yt-dlp/releases/tag/2026.10.26) と [FFmpeg・ffprobeのWindows版](https://github.com/GyanD/codexffmpeg/releases/tag/9.1) です。

拡張フォルダーを移動した場合は、その場所でセットアップを再実行してください。接続登録を解除するには、同じ配布フォルダーで `Windows-Setup.cmd -Remove` を実行します。

## その他の保存方法

動画を一度再生して拡張を開きます。候補が出る前に開いた場合は「再検出」を押してください。

| 拡張で選ぶ項目 | 保存される内容 |
| --- | --- |
| ファイルを保存 → ダウンロード | MP4・WebMなどの動画ファイルを元の形式で保存します。元タブに取得と保存の進捗を表示します。 |
| 検出したHLS配信 → 取得を開始 | HLSのライブまたはアーカイブを取得してMP4に保存します。 |
| キャプチャモード → キャプチャを開く | 選んだプレーヤーで再生した区間を録画します。Chromeが利用できるMP4・WebMから形式を選べます。 |

**冒頭からキャプチャするには**、動画を読み込んだ後、先頭で一時停止します。「キャプチャを開く」→「録画を開始」を押し、「動画のタブを表示」で戻って再生します。動画の終了または「録画を停止」で指定フォルダーに保存します。「毎回選ぶ」の場合は「保存」で保存先を選べます。録画中は動画タブとキューを開き、保存したい区間を再生してください。

別サイトのプレーヤーが埋め込まれている場合は、「別サイトの埋め込みを調べる」を開き、対象の配信元で「許可して検出」を押します。HLSの保存でも、プレイリストや動画区間を配信するホストの読み取り許可を求める場合があります。

## 対応範囲

- HTTP・HTTPSページの動画要素、動画ソース、対応する動画メタデータ、読み込み済みの配信情報から候補を探します。
- 通常モードは非暗号化HLSに対応します。複数画質では、元タブのプレーヤーが読み込んだ映像の解像度と、同じプレーヤーで検出した映像プレイリストが1つに一致すると、その画質を取得します。再生前で解像度が不明な場合、候補を区別できない場合、URLを手入力した場合は最大帯域の映像を選びます。音声は選んだ画質に対応する音声グループの既定音声を使います。既定指定がない場合は自動選択の指定、次に掲載順を使います。
- 別配信の分割MP4、MPEG-TS、時刻情報付きの単独AAC音声を、拡張内で再エンコードせずに結合します。映像と音声はそれぞれの区間を取得し、再生時刻を合わせます。両側に配信日時がある場合はそれも同期に使います。途中でライブを止めた場合は両方がそろった連続部分を保存します。結合には同梱のMediabunny 1.66.2を使います。ライセンスは `extension/vendor/mediabunny-LICENSE.txt` にあります。 [Mediabunny 1.66.2のソースを含む公式配布物](https://registry.npmjs.org/mediabunny/-/mediabunny-1.66.2.tgz)
- 映像と音声をすでに含む分割MP4は元のまま保存します。H.264映像とAAC音声を含むMPEG-TSは、同梱のmux.js 6.3.0でMP4に変換します。 [mux.jsの配布元](https://github.com/videojs/mux.js)
- ライブは区間番号で重複を防ぎます。低遅延HLSは公開済みの完全な区間を扱います。欠落や映像・音声の切り替えがある場合は、その手前までを残して終了します。アーカイブでは結合できない区間を検出した時点で通知します。HLS取得にはサイトのログインCookieを送信しません。
- 再生録画はChromeが取得を許可したプレーヤーが対象です。DRM保護作品は対象外です。録画対象は動画要素の出力で、ページ上に重ねられたコメントや別要素の字幕は含みません。
- 自動検出をオンにすると、タブごとにレスポンスのURLと配信形式からHLSを見分けます。候補のURLはChromeのセッション内で扱い、タブを移動・終了した際に更新します。保存処理はPC内で行います。

### バージョン1.3.0の自動検出とMP4保存

- 初回の許可後、別オリジンのiframeが読み込んだ、拡張子のないHLSを配信形式で検出。対象タブだけに「HLS」が付き、アイコンをクリックすると取得画面が開きました。マスターとその画質候補は1配信、独立した2配信は選択肢として表示されました。
- 6秒のH.264＋AACアーカイブ、配信終了までの4秒のライブ、手動停止した2秒のライブをMPEG-TSからMP4に変換。3本とも、変換前後の全映像フレームと音声サンプルをデコードしたSHA-256が一致しました。分割MP4のアーカイブでは保存ファイル全体が元の区間の連結と一致しました。
- 約2分45秒、41区間のMux公開HLSを音声付きMP4に保存。Chromeで保存結果を開き直し、2分40秒の位置にシークできました。 [Muxの公開テスト配信](https://test-streams.mux.dev/)
- HLSがない動画ページではキャプチャモードで約6秒の再生を音声付きMP4に録画しました。通常モードでは保存ダイアログのキャンセル後も再取得せずに保存でき、同じ配信でアイコンを再度押すと元の取得タブに戻りました。

上記の自動テストでは一時Chromeプロファイルで実際の読み取り許可を与えました。拡張のバックグラウンド処理が休止した後も、新しいページで自動検出が再開しました。保存先の選択はテスト用ファイルハンドルを使い、書き込まれたファイルを個別に検証しました。自動検出をオフにするとテスト開始時に追加した全サイトへの許可が解除されました。
